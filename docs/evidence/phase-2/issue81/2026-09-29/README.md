# Issue #81 implementation and verification evidence

## Scope and revisions

Issue [#81](https://github.com/DomineYH/vibe_coding_archive/issues/81), under [Phase 2 spec #77](https://github.com/DomineYH/vibe_coding_archive/issues/77), completes the public list query contract and activates the existing `apps_read` capability. The implementation is commit [`e09fecc`](https://github.com/DomineYH/vibe_coding_archive/commit/e09fecc), followed by test-boundary commit [`ad6b4ea`](https://github.com/DomineYH/vibe_coding_archive/commit/ad6b4ea), fix-round-one commit [`ba734d1`](https://github.com/DomineYH/vibe_coding_archive/commit/ba734d1), and fix-round-two source commit [`d406d53`](https://github.com/DomineYH/vibe_coding_archive/commit/d406d53b89b5ac3620abffaed5f85f44dfed4443). Fix round one rejects query input on public detail with a 400 `VALIDATION_ERROR`, updates its OpenAPI response and generated TypeScript, strengthens privacy fixtures, and extracts shared API E2E utilities. Fix round two allows the detail validation error through the shared service and shares viewport preparation between API E2E specs.

Search trims ECMAScript whitespace, applies NFC and Unicode casefold, enforces 100 folded code points, and performs literal substring matching independently on public app name, owner nickname, and description. Subject and grade filters combine with search using AND. The route strictly parses raw query bytes, rejects repeated and unknown keys, invalid percent/UTF-8, invalid filters and numeric values, and does not clamp limits. Ordering remains `created_at DESC, id DESC`; totals and pages use the filtered set, while subject facets use the complete public set in catalog order.

The OpenAPI source and generated TypeScript declare the list query parameters; fix round one adds detail's 400 validation response and regenerates the corresponding TypeScript operation type. Backend HTTP contract tests compare FastAPI declarations and normalized DTO schemas to OpenAPI. `apps_read` is enabled only after list/detail, query, and redaction checks pass; other capabilities retain their prior disabled reasons. Public responses expose no login, contact, password, prompt-only, private-row, or health-job data. The UI receives real owner nicknames and stored `unchecked` health, and makes no auth, CSRF, health, write, or administrator calls.

TDD evidence: before implementation, the added list-query contract tests failed against the old route (3 failed, 18 passed). For fix round one, the four detail-query cases failed first because the route returned 200; after the change, the focused contract set passed 7/7 and the final backend suite passed 61/61. The first API browser run exposed invalid all-zero UUIDs in the shared test fixture; API E2E now opts into valid synthetic UUIDs to satisfy the existing strict frontend mapper. Subsequent failures were corrected test locators, not server behavior. The final actual API browser run passes 3/3.

## Test data and visual evidence

The API E2E wrapper migrates and owns a temporary file SQLite database and seeds 27 public synthetic apps plus a private sentinel row whose subject (`기타`) is absent from public rows. The seeder lives in an importable test utility shared by pytest and the API runner. It does not call the development seed or persist data. The public/detail browser flow checks real metadata and list responses, a composite query (`q` + subject + grade), the next page, normal zero results, private detail 404, detail reload and return, unchecked health, explicit list retry after a 503, no auth/CSRF/health endpoint call, and blocked external requests.

The [API-mode capture directory](visual/api-mode/) contains 45 PNGs: 35 full-page captures across the public gallery, composite-filtered results, zero results, detail, list error, metadata failure, and held loading state at the five fixed viewports, plus 10 status crops for the failure and loading states. Fix round one removed an early `filtered` capture that the post-pagination capture overwrote and refreshed only the five committed `filtered` images after pagination. The [comparison record](visual/api-mode/comparisons.json) remains at 35 records and its filtered dimensions still match. Synthetic card content changes page height, so gallery, filtered, and detail comparisons record dimensions without padding or pixel claims. Zero-result and list-error screens are pixel-compared with their mock references. Metadata failure/loading match the prior API state at four viewports; their 390×844 captures each differ by 16 pixels. These differences remain visible for human UI-D review; `human_approval` is pending. No visual baseline or source reference changed.

The API browser tests use accessible names/roles for search, filters, links, retry, and page controls, check that the document does not overflow each viewport, verify keyboard retry focus during metadata loading, and assert `rel="noopener noreferrer"` on the external app link. These desktop Chromium checks do not constitute physical-device, screen-reader, or human visual approval.

## Fix round four verification

The implementation is commit [`332c781981232cb132600484258c49f3a76ea094`](https://github.com/DomineYH/vibe_coding_archive/commit/332c781981232cb132600484258c49f3a76ea094), followed by formatting-only source commit [`9a8386e25f72c5e06db8266bed51d78dc2db33db`](https://github.com/DomineYH/vibe_coding_archive/commit/9a8386e25f72c5e06db8266bed51d78dc2db33db). The required full-suite results below ran against source commit `9a8386e25f72c5e06db8266bed51d78dc2db33db`.

The mismatch is confirmed: pinned Python 3.12.3 uses Unicode 15.0.0 and leaves U+A7CC (`Ꟍ`) unchanged under `casefold()`, while the frontend JavaScript runtime used Unicode 17.0 and folded it to U+A7CD (`ꟍ`). Before the fix, `appsService.list({ q: "  Ꟍ  " })` sent `ꟍ`; its new real-client-path regression failed with expected `Ꟍ`, received `ꟍ`. The client now sends trimmed NFC text without case folding; the backend is authoritative for matching and the 100-code-point limit. Client folding remains a UI length hint, and the deterministic mock folds both its query and fields to retain local behavior.

The backend contract now searches for `Ꟍ` in a stored public description. The error contract test seeds its public/private rows, adds a public sentinel, triggers the storage failure, and checks list and detail error bodies and headers for all seeded sentinels.
