# Issue #82 implementation and verification evidence

## Scope and revisions

Issue [#82](https://github.com/DomineYH/vibe_coding_archive/issues/82), under Phase 2 spec [#77](https://github.com/DomineYH/vibe_coding_archive/issues/77), connects the existing gallery controls to the public search and paging API. It follows the decisions in #8 and #12 and reuses the #81 API contract. The app change is limited to preserving an over-limit direct search value while hiding results and suppressing the API request, and keeping a valid selected subject visible if the current response's facet list no longer contains it.

Implementation commit [`13027e08734dd6ed00612e08e139ce014a934c94`](https://github.com/DomineYH/vibe_coding_archive/commit/13027e08734dd6ed00612e08e139ce014a934c94) is followed by test commits [`99e471c2710522fb5e143b2d8eb9222234703d0a`](https://github.com/DomineYH/vibe_coding_archive/commit/99e471c2710522fb5e143b2d8eb9222234703d0a), [`29e7d7570619770ea6fd2e029814078d4e71b6b1`](https://github.com/DomineYH/vibe_coding_archive/commit/29e7d7570619770ea6fd2e029814078d4e71b6b1), and [`6fcad64961173fbc9f3ad550565f71a62dc388c5`](https://github.com/DomineYH/vibe_coding_archive/commit/6fcad64961173fbc9f3ad550565f71a62dc388c5). The intermittent IME failures were a test-harness timing race. Playwright `page.clock.install()` installs fake timers but leaves the clock advancing with real time. Under four-worker contention, the 300 ms debounce could fire between the `compositionend` dispatch and the next Playwright call that advanced the clock by 299 ms. The app's debounce remains 300 ms; no product UI code changed.

- Before the fix, the CI-like command failed 18 of 50 runs (13 at the first boundary and 5 at the grade boundary). Hosted failures included runs `36535378783` and `36535382533` on the wall-clock boundary, plus `36543504928` on the grade boundary; parallel run `36543513244` passed.
- The test now pauses the clock before composition interactions, resumes only for the in-composition viewport capture, pauses again before `compositionend`, and advances 299 ms then 1 ms deterministically. Zero-time advances flush query notifications after API responses without resuming the clock.
- The identical controlled 503 response body in the refetch, race, and paging specs now comes from `fulfillServiceUnavailable()` in the shared E2E helpers.
