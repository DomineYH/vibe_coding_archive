# Issue #78 public-read preparation and error boundary — 2026-09-28

## Scope and result

Implements [issue #78](https://github.com/DomineYH/vibe_coding_archive/issues/78), the #77 T01 prefactor. The API frontend starts with authentication explicitly unavailable, so public metadata/list/detail reads do not wait for API auth restore. Canonical `GET /apps` `400 VALIDATION_ERROR` responses map to `ServiceError`; the gallery keeps the entered query, links `fields.q` to an invalid search field and visible field message, and offers an explicit reset. The R2 API-mode smoke also checks hidden-tab auth availability and intercepted `fields.q` behavior at five viewports, including keyboard reset. Mock auth and write behavior remain unchanged.

R2 `npm run check`, unit (28 files/412 tests), E2E (106/106), visual (122/122 with baseline capture disabled), API-mode smoke, and API build/distribution checks pass. Full unit/E2E/visual suites ran before reverting a one-line-larger unavailable-route helper; because that cleanup restores the original, output-equivalent route markup, the final source was rechecked with `npm run check`, focused gallery tests, API-mode smoke, and build/distribution checks. The source-reference hash check was not rerun in R2; its earlier implementation-commit pass remains separately identified below. This does not implement or verify a live backend, database, authentication, writes, admin API, or connection checks. API-mode browser evidence below uses controlled Playwright route responses. Human source-difference/UI-D review and DomineYH's local handover acceptance remain pending.
