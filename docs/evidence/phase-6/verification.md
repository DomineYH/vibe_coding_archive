# Phase 6 구현 검증 — 2026-10-07

브랜치 `feat/phase-6-health-checks`, 비교 기준 `dc4898f`.
작업은 사용자의 권장안 일괄 위임으로 진행했다. 운영 활성화와 실제 외부 송신은
실행하지 않았다. 아래 로컬 검증과 실제 호스트 검증을 구분한다.

## 로컬 검증

Python 3.12.3 및 잠금된 의존성, Node 22.23.2/npm 12.0.2로 검증했다.
Windows 마운트의 파일 지연 때문에 전체 회귀는 동일 소스를 Linux 임시 복사본으로
실행했다. 전체 회귀 복사본 이후 바뀐 worker, URL 변경 처리 및 영향 테스트는
최종 소스의 별도 복사본으로 재검증했다. 최종 복사본의 Python
138개 파일은 현재 소스와 모두 일치한다. 사용자 DB·설정·미커밋 문서는 변경하지 않았다.

전체 회귀의 실패 15개는 다음처럼 해소했다. 공유 schema·설정의 전체 영향은
한 번 실행했고, 수정 후에는 영향 파일을 재실행했다. 전체 회귀를 최종 소스로
다시 실행했다고 주장하지 않는다. 남은 미해결 테스트 실패는 없다.

- 10개: `health_read`, migration head `0012`, 새 GET 경로의 PATCH 405 및
  추가 health 열을 반영해 기존 계약을 갱신했다. 이전 열의 모든 값 보존과
  downgrade 거부 검증을 유지했고, 해당 7개 파일의 79개 테스트가 통과했다.
- 4개: 인증 유지보수 fixture가 새 health 유지보수의 5초 sleep까지
  인증의 60초 sleep으로 가정했다. health loop에는 실제 sleep을 위임하고
  인증 loop만 제어하도록 고쳤다. 해당 인증 파일을 포함한 86개 테스트가 통과했다.
- 1개: URL 변경 trigger가 health 결과를 DELETE한 뒤 INSERT하므로 이전
  UPDATE 장애 주입이 실행되지 않았다. DELETE·INSERT 각각의 실패와 모든
  관련 행·작업의 원자적 롤백을 검증했다. 같은 경로에서 초기화 행의 URL 버전이
  1로 남는 문제도 새 검증으로 재현했다(1 FAIL / 2 PASS). 현재 URL 버전을
  명시하도록 수정했고, 소유자·관리자의 URL/fragment 및 측정값 보존·초기화를
  포함한 영향 회귀 86개가 통과했다.

- 검사 공개 함수: 통제 DNS/HTTP에서 결과 분류, 차단, IP 고정, TLS 정책,
  HEAD→GET, redirect, 헤더 상한, 실제 10초/3초 기한과 소켓 종료를 검증했다.
- 저장소/API: migration된 임시 SQLite와 실제 HTTP 인증 흐름으로 원자성,
  현재 권한, 중복·제한, 배치 대상 고정, 삭제/URL 변경, 만료·보관을 검증했다.
- 별도 프로세스: 4개 시나리오 통과(129.54초). 최대 3개 실행과 대기 보존,
  SIGTERM 종료, 두 번째 프로세스의 잠금 거부, SIGKILL/OS exit/소켓 EOF 확인,
  실제 60초 cooldown·동일 ID의 두 번째 시도·횟수 소진, 명시 중지를 관찰했다.
- lease 만료 회귀: 수정 전 실제 소켓은 닫혔지만 `running`이 남았다.
  수정 후 1개 테스트 통과(11.16초): 자원 종료 뒤 복구, cooldown 유지,
  같은 작업 최대 2회와 이전 연결 결과 보존을 확인했다.
- 브라우저 첫 결합에서 관리자 배치는 통과했고, 익명 개별 검사는 인증 흐름이
  준비되지 않아 실패했다. 기존 익명 인증 준비 절차를 재사용하도록 수정한 뒤
  익명 검사·관리자 행별 검사·전체 배치·새로고침 후 영속 결과 확인이 모두 통과했다.

## 코드 검토

`code-review`의 Standards·Spec 축을 병렬 검토했다.
Standards의 문서화된 위반은 없었고, 라우터 사이 가용성 함수 의존성은 개선
판단 1건이었다. Spec은 VM 재개와 DB 잠금 사이의 저장 경계(P1), 관리자 오류
분류·단계 불일치(P2)를 발견했다. 공통 runtime으로 의존성을 정리하고 오류 분류
57개 테스트를 통과했다. 시계 기준은 claim 전부터 DB 잠금 이후·commit 직전·
probe 직전까지 유지한다. 후속 검토의 명시적 중지 경합도 결과 저장과 정상 종료
drain 중까지 적용했다. 별도 실제 호스트 검증을 통과한 것으로 해석하지 않는다.
마지막 URL 변경 처리와 유지보수 fixture 수정도 두 축으로 검토했으며 추가
지적은 없었다.

## 실제 호스트·활성화 기록

[운영 절차](../../operations/health-checks.md)의 8개 검증 그룹은 모두
**NOT RUN**이다. 통제 I/O와 Linux 로컬 프로세스 결과를 해당 호스트의 PASS로
복사하지 않는다. 실제 DNS/TLS·송신망 결합, 실제 VM suspend/reboot,
배포 supervisor·OOM 및 실제 DB 실패 검증은 수행하지 않았다.
운영자 활성화 승인 기록은 생성·완성하지 않았으며 기본 비활성을 유지했다.
