# Issue #49 full journey and local handover record — 2026-09-27

Scope: connect the already implemented Phase 1 mock flows from registration through administration, app editing, health checks, deletion, logout, and explicit reset. All account/app values in the run are synthetic. No backend, database, worker, external URL request, deployment, or public-release behavior is implemented or claimed.

Branch: `impl/issue-49`.

## Implementation trace

The UI follows the existing pipeline: `contracts/openapi.yaml` → generated types → strict mappers → Promise services → deterministic mock → product routes. The only production change fixes mock-state validation: a registered account is now a valid owner of a private app. The pre-existing validator only allowed seeded mock accounts, so a newly registered member could create an app but switching it to private made subsequent mock reads fail with `MOCK_STORAGE_ERROR`.

The new browser flow registers and approves a synthetic member; logs in; creates, reads, edits, privately saves, and republishes an app; runs its individual check and an admin whole-app batch; deletes the account and its owned app; logs out; and explicitly resets. It also hides an unsaved draft on auth-observation failure and restores it only after retry, starts a delayed app update and holds a batch read in flight during account deletion, then confirms the batch target is cancelled, the late batch read sees that cancellation, dashboard counts decrement, and neither app nor account returns. Direct entry, reload, history, a second tab, and a delayed create response after reset remain covered.
