## Visual comparison record

The required viewports are `1440×1000`, `1024×900`, `768×1024`, `390×844`, and `360×844`. The visual run now uses the source renderer, matching layout/date/icons, the original 16-item fixture, and the full capture sequence. All 32 comparisons now pass at zero tolerance (0 differing pixels, maximum channel delta 0); no UI-D candidate remains.

The three states without supplied source captures use product-only regression references in [`visual-state-baselines/`](evidence/phase-1/issue31/2026-09-25/visual-state-baselines/). They were re-captured with the source renderer after the prior captures were found to use a different renderer. The original source references and zero threshold were not changed. Screenshots and per-case metrics are [`visual-comparison.json`](evidence/phase-1/issue31/2026-09-25/visual-comparison.json) and the adjacent PNGs.

Five source-only fresh-context replays retain raster differences against the preserved reference (129–131 of 135 captures were pixel-identical); all five failures and their pixel counts remain in [`original-repeat-summary.json`](evidence/phase-1/issue31/2026-09-25/original-repeat-summary.json). The cause investigation is **INCOMPLETE**, so acceptance criterion AC7 is **BLOCKED**. Source hashes, browser/HAR/runtime, recorded state/font metrics, and page/network errors were ruled out. For the 360px empty-gallery capture, the five source-reference counts were 20/18/20/0/89 pixels. A focused rerun mapped the 89-pixel outlier to text pixels in the five subject-filter buttons (16/18/18/18/18) plus one row-container pixel. Exact-sequence captures at 400ms and 800ms after blur both remained 89 pixels from the reference and were 0 pixels apart; focus, scrollbar, caret, animation, and post-blur wait timing were ruled out, but the cause of cross-context glyph raster differences remains unknown. Product-to-source comparison remains 32/32 exact at zero tolerance. No source baseline update, tolerance, or visual exception was needed.

## Issue #36 auth refresh and protected-screen concealment

The public gallery/detail layout remains available while auth is observed. Private detail and the admin placeholder switch to the existing EmptyState treatment when an auth transition starts, the window loses focus, or the tab becomes hidden. On return and browser history traversal, the current mock principal is checked before private detail returns. Observation errors keep private detail hidden and expose an explicit retry; a communication error does not count as logout.

The fixed five-viewport auth run adds product-only captures for concealed, auth-checking, auth-observation-error, and restored private detail. There is no supplied source screenshot for these transient states. Existing source references, product baselines, and zero pixel tolerance remain unchanged. Screenshot captures record the implemented appearance; visual approval remains with DomineYH.

The same-origin mock principal is shared through the existing mock store. An auth-scope change cancels outstanding private-detail reads and clears their cached result; public gallery and public detail data remain auth-independent. `last_identity_change_revision` distinguishes A → logout → A even when the final member is the same. The local client observation counter rejects stale refresh results; mock reset invalidates old delayed work. These are deterministic mock behaviors and do not verify real cookie, HTTP, server, or database isolation.

The issue #33 corrupt-storage recovery screenshot remains preserved as its original baseline, but the #36 matrix records the current header-level auth retry at five viewports as product-only. Its UI contract changed with the explicit auth-observation retry; no baseline or pixel threshold was edited. The other 57 gallery visual captures still compare exactly with their existing baselines/references.

The implementation remains in the original application shell and detail/admin routes. It adds no new page or navigation flow. Keyboard and screen-reader coverage is automated in auth E2E tests; human UI-D and local-handover approval remain pending. See the [#36 run evidence](evidence/phase-1/issue36/2026-09-26/README.md) for screenshots, relevant #23 case mapping, and verification results.
