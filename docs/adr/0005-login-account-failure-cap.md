# 로그인 실패에 IP와 무관한 계정 단위 상한(15분 50회)을 둔다

[#278](https://github.com/DomineYH/vibe_coding_archive/issues/278)에 따라 회원 로그인과 관리자 재인증의 실패를 IP와 무관하게 로그인 아이디 키 기준으로도 센다. 같은 계정의 실패가 rolling 15분에 50회에 이르면 어느 IP에서든 그 계정의 로그인·재인증을 `429 RATE_LIMITED`와 재시도 시점(`retry_at`, `Retry-After`)으로 막는다. 기존 제한인 같은 IP에서 같은 계정 15분 10회, 한 IP 전체 15분 200회는 그대로 둔다. 기록은 `rate_limit_events`의 새 용도 `login_account_global`과 정규화한 로그인 아이디 키의 `digest()`만 쓰며, 원문 아이디·IP·비밀번호는 저장하지 않는다. 존재하지 않는 아이디도 같은 방식으로 세므로 50회 뒤의 응답은 존재하는 계정과 같다. 로그인 실패와 재인증 실패는 같은 계정이면 한 창에 합산된다. 차단된 시도는 기록하지 않아 창을 늘리지 않고, 성공 로그인은 실패 기록을 지우지 않는다. 이 창이 막을 때 `LOGIN_ACCOUNT_LIMITED` 로그 이벤트를 경로와 상태만으로 남긴다. 값은 `backend/app/auth_login.py`의 `ACCOUNT_GLOBAL_FAILURES`이고 창은 기존 `WINDOW`(900초)를 공유한다. 용도 컬럼이 자유 문자열이라 마이그레이션은 없다.

[ADR 0004](0004-password-minimum-length-8.md)는 새 비밀번호 최소 길이를 8자로 낮추면서, 계정 단위 제한이 IP와 묶여 있어 여러 IP로 나눈 같은 계정 추측에는 계정 기준 상한이 없다는 잔여 위험을 받아들였고, 이 제한의 도입을 재검토 조건으로 적었다. 공격자가 IP N개를 쓰면 기존 제한만으로는 한 계정에 15분 10×N회를 시도할 수 있다. 50은 IP 5개분이라 분산 추측을 IP 수와 무관하게 15분 50회로 묶는다. 정상 사용자가 15분에 50회 틀리기는 어렵고, 한 IP에서는 이미 10회에서 막힌다.

이 상한은 타인의 계정을 막는 잠금 DoS에 쓰일 수 있다. 그 비용과 효과는 다음과 같이 제한된다. 공격자는 한 계정에 15분 50회 실패를 만들어야 하므로 IP당 10회 제한 때문에 IP 5개 이상이 필요하다. 효과는 최대 15분의 로그인·재인증 지연이며 창이 지나면 자동으로 풀린다. 제한은 로그인·재인증 전환에서만 판정하므로 이미 발급된 세션은 폐기되지 않는다. 운영자의 해제 조작이나 관리자 임시 비밀번호 발급([#274](https://github.com/DomineYH/vibe_coding_archive/issues/274))에 의존하지 않고 복구된다.

점진적 지연은 기존 `fail()`·`refuse_when_limited`에 없는 대기 상태가 필요하고, 해싱 게이트(실행 2·대기 4)를 점유하는 대기가 503 `AUTH_BUSY` 표면을 키워 기각했다. 일 단위 상한은 새 창 길이와 만료 처리가 필요하고 잠금 DoS의 지속 시간만 늘려 기각했다. 현상 유지는 ADR 0004의 재검토 조건이 이 제한을 가리키고 변경 비용이 작아 기각했다. CAPTCHA·하드 잠금·가입 제한 변경은 범위 밖이다.

운영 로그에서 `LOGIN_ACCOUNT_LIMITED`가 정상 사용자 불편으로 이어지면 값을 올리고, 분산된 추측 시도가 관측되면 값을 낮추는 것을 검토한다. 다중 인증을 도입하거나 기존 계정+IP·IP 제한을 바꾸면 이 결정을 다시 검토한다.
