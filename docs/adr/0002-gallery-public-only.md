# 갤러리 목록·검색·집계는 모든 사용자에게 공개 앱만 제공한다

OpenAPI `GET /apps`의 summary ‘List public archive apps’와 `security: []`는 이미 공개 읽기를 정의한다. facets 설명의 ‘full accessible set’도 현재 갤러리에서는 공개 앱 전체를 뜻한다.

PRD GAL의 ‘로그인 사용자가 볼 수 있는 비공개 앱’ 문구가 실행 코드와 OpenAPI의 공개 전용 갤러리 계약에 충돌하므로, [#226](https://github.com/DomineYH/vibe_coding_archive/issues/226)의 유지관리자 권장안 적용 위임에 따라 갤러리 목록·검색·페이지 집계(`total`)·과목 집계(`facets`)는 익명·소유자·다른 회원·관리자 모두 공개 앱만 대상으로 하며 인증 헤더 없이 읽는다. 이는 [#81](https://github.com/DomineYH/vibe_coding_archive/issues/81)의 공개 전체 집합 facets, [#23 확정 결정](https://github.com/DomineYH/vibe_coding_archive/issues/23#issuecomment-5806449465)의 무헤더 익명 읽기 경계, [#222](https://github.com/DomineYH/vibe_coding_archive/issues/222)의 공개 갤러리 유지와 [현재 OpenAPI](../../contracts/openapi.yaml)에 맞춘 결정이다. [#8](https://github.com/DomineYH/vibe_coding_archive/issues/8)의 ‘접근 가능한 전체 집합’은 현재 갤러리에서 검색·필터·페이지 적용 전 공개 앱 전체를 뜻하며 비공개 상세 권한을 목록에 확장하지 않는다. [#12](https://github.com/DomineYH/vibe_coding_archive/issues/12)의 Phase 2 비공개 조회 유예는 과거 단계 기록으로 유지하며 이번 결정을 소급해 정당화하는 근거로 삼지 않는다. [#120](https://github.com/DomineYH/vibe_coding_archive/issues/120)에서 구현한 비공개 상세(`GET /apps/{id}`)는 승인 full 소유자/관리자의 기존 권한을 유지하고 중복 구현하지 않으며, 관리자 앱 관리 목록(`GET /admin/apps`)은 공개·비공개 전체 앱을 유지한다. 공개 앱 상세도 #222의 승인 full 세션·비밀번호 변경 불필요 조건을 따른다. 소유자도 자신의 비공개 앱을 갤러리에서 발견할 수 없다는 한계가 남는다. 개인화 갤러리와 ‘내 앱’ 화면은 이번 범위 밖이며 후속 이슈에서 다룬다.
