# 관리자 회원 삭제

준비된 development API와 명시적 격리 인증 테스트에서 기존 회원 행의 삭제 버튼을 사용한다. 현재 승인 full 관리자가 15분 이내에 재인증해야 하며 관리자 본인과 다른 관리자 계정은 삭제할 수 없다. 비밀번호 초기화용 비밀 공급은 이 기능의 조건이 아니다. production 공개와 전체 앱 관리 기능은 별도 gate다.

`user_delete` 키 발급과 DELETE는 `expected_app_count`만 확인한다. 앱 수가 같으면 실행 시점의 현재 소유 앱 전체를 삭제한다. 계정 버전과 앱 ID 목록은 추가 조건이 아니다. 취소 버튼은 제출 전 패널을 닫는다. 계정 삭제 키는 취소 API 대상이 아니다.

회원, 앱, 학년, 연결 결과, 모든 대상 세션, 대상이 발급한 작업 키와 관련 인증 권한을 한 트랜잭션에서 정리한다. 호출 관리자 결과와 다른 회원의 최소 과거 결과, 기존 앱 삭제 outbox는 보존한다. 신규 검사 작업/배치 schema는 구현하지 않는다. 향후 검사 작업은 삭제/취소, 요청자 NULL, 배치 원문 제거와 확정 집계 보존을 적용하고 늦은 결과가 삭제된 ID를 재생성하지 않도록 해야 한다.

DB 적용 후 기존 독립 `.deletions.sqlite3` 파일의 `completed_user_delete_events`에 회원과 앱 묶음을 전달한다. 운영 DB의 `user_delete_outbox`와 원장은 대상/작업 키 FK 없이 의무를 보존한다. 모든 이벤트의 수와 manifest를 확인하고 최종 결과까지 기록한 경우에만 빈 204를 반환한다. 204는 확정 성공이다. 추가 GET은 필수가 아니다.

독립 확인과 최종 acknowledgement에 합계 5초를 사용한다. 503 `DELETION_CONFIRMATION_PENDING`은 삭제가 DB에 반영됐지만 확인 대기 중임을 뜻한다. 회원과 앱은 이미 조회/로그인/통계에서 제거됐다. 기존 키 조회 패널을 유지하고 기존 1분 유지보수는 전달만 재시도한다. 유실/401/기타 503/조회 404·410은 과거 성공 또는 실패의 증명이 아니다. 자동 새 키 발급이나 재삭제는 하지 않는다. 앱 수 충돌 후 최신 정보를 명시적으로 확인하고 다시 제출한다.

## 마이그레이션과 복원

실제 개발 DB 변경은 운영 담당자의 승인된 rollout에서 수행한다. 모든 쓰기를 중지하고 WAL을 포함하는 검증된 SQLite backup과 **현재 독립 원장**을 각각 보존한 후 backend에서 `APP_ENV=development uv run --frozen alembic upgrade head`로 `0010_password_reset` → `0011_user_delete`를 적용한다. 기존 종류/결과/감사/app outbox를 보존하며 downgrade는 거부한다. 정상 live startup만 새 독립 테이블을 준비할 수 있다. 초기화/검증 전에는 capability가 비활성이다.

복원 전에 현재 DB의 미전달 app/user outbox를 전달하고 전체 독립 증거를 검증한다. 전달이 막혔다면 현재 DB/outbox를 보존하고 서비스를 닫은 상태에서 증거를 복구한다. 과거 백업과 함께 독립 원장을 되감지 않는다. 이전 schema 백업은 닫힌 상태에서 0011로 올린 뒤 기존 `invalidate-restored-auth` 절차를 적용한다.

복원 preflight는 모든 app/user 증거를 확인한 후에만 재삭제를 시작한다. 기존 최초 승인 대기 정리의 증거 검증·재적용도 유지한다. 회원, 당시 기록된 앱 ID와 복원된 현재 소유 앱 전체를 삭제하고 모든 과거 작업 키/세션/복구 권한을 무효화한다. 누락/부분/충돌 증거는 재개를 막는다. 복원 DB로 누락 원장 이벤트를 만들어 성공 처리하지 않는다. 백업과 원장 양쪽에 완전히 사라진 사건은 코드로 추론할 수 없으며 현재 원장과 복사본 목록이 복구 전제다.

모든 관련 백업/복사본 만료 확인 후 7일이라는 보관 조건을 유지한다. 현재 코드는 그 증명이 없으므로 삭제 기록을 자동 제거하지 않고 원래 DB 적용 시각을 연장하지 않는다. 최소 업무 감사는 법정 접속기록 체계 완성과 구별한다.
