## 1. 조사 개요 및 요구 조건 경계 (Scope & Boundaries)

### 1.1 조사 목적
본 조사는 EduVibe 아카이브가 수립한 운영 호스트·도메인·백업·공지·비용 정책([Issue #10](https://github.com/DomineYH/vibe_coding_archive/issues/10)의 Q1~Q45 확정 입력)을 만족할 수 있는 **임대 Linux VM 후보 최대 2개**와 이에 호환되는 **독립 암호화 백업, 주/예비 운영메일, 도메인/DNS, 독립 공지** 조합을 대한민국 공급자의 공식 1차 자료(Primary Sources)에 근거하여 엄밀히 검증하고, 조건별 충족·미충족·미확인 사실과 총비용을 명시하는 것을 목적으로 한다.

### 1.2 승인된 조사 경계 (Q24)
1. **대상 환경 (Single Host Linux VM)**:
   - 운영자가 OS 및 송신망을 통제하는 임대 Linux VM.
   - 단일 호스트, 로컬 영속 SQLite, 애플리케이션 API와 별도 worker 프로세스 분리 운용, 동일 출처 HTTPS.
   - 하드웨어 체급: **2vCPU / 4GB RAM급**. (사용자 1,000명, 등록 앱 5,000개, 읽기 동시 접속 50명, 목록/상세 API p95 500ms는 구현 후 검수 목표이며 공급자 문서상의 처리량 보증으로 대체하지 않음).
2. **저장 및 공급자 분리 원칙**:
   - **운영 DB 및 백업**: 반드시 **대한민국 국내 리전(Domestic Region)** 후보로만 제한.
   - **암호화 백업**: 운영 VM 공급자와 **다른 국내 공급자**이며, **별도의 독립 계정**이어야 함.
   - **주/예비 운영메일**: 본문, 첨부파일, 백업 모두 **국내 저장** 후보로 제한. 웹 호스트 및 서비스 도메인과 완전 독립.
   - **도메인 등록 및 DNS**: 운영 VM 공급자와 완전히 분리.
3. **독립 공지 채널**:
   - 운영 VM, 서비스 도메인/DNS, 운영메일 계정의 동시 접근 상실(전면 장애/탈취/잠금) 시에도 즉시 게시·복구 가능한 독립 공지 구성. 단순 브랜드 분리가 아닌 **실제 장애·인증·복구 의존성의 독립** 검증.
4. **비용 및 예산 임계치 (VAT 10% 포함 기준)**:
   - **월 환산 총액 상한**: **50,000원 이하** (모든 인프라, 백업, 도메인, 메일, 트래픽, 세금 포함).
   - **선결제 한도**: 초기 설치비 및 갱신 선결제는 **건당 100,000원 이하**.
   - **운영 임계치 여유도 표시**:
     - **40,000원 경보선 (Alert Threshold)**: 예상 월 총액 40,000원 도달 시 경보 발령 (Q21/Q31).
     - **45,000원 제한선 (Throttling Threshold)**: 예상 월 총액 45,000원 도달 시 비용 발생 경로 제한 (Q21/Q31).
   - 프로모션 할인 배제(정상/갱신 요금 기준), 최소 결제 단위, 중단 후 남는 고정요금 분리 명시.
5. **보관·삭제 및 복구 목표**:
   - 고객 제어 복사본과 공급자 자동 백업/스냅샷/휴지통/계약 종료 후 잔여 데이터 엄격 구분.
   - 최대 30일 복사본 보관, 복사로 인한 만료 연장 금지, 삭제 재적용 원장 지원 가능 여부 확인.
   - RPO(목표 복구 시점) 최대 24시간, RTO(목표 복구 시간) 48시간 목표.

### 1.3 판정 원칙 및 Q33 처리 기준
- **[충족 (Confirmed Met)]**: 직접 열람한 공식 1차 자료의 정적 텍스트에 명시적으로 확인된 경우.
- **[미충족 (Unmet)]**: 직접 확인한 공식 1차 자료상 요건을 위반하거나 예산·기술 조건을 명백히 초과/미달하는 경우.
- **[미확인 (Unverified)]**: 공식 문서에 수치가 누락되어 있거나, 인프라 레벨의 지원 여부가 명시되지 않았거나, 브라우저 자바스크립트(JS) 렌더링에만 의존하여 정적 텍스트로 확증되지 않은 경우. **미확인은 절대로 충족으로 간주하지 않음**.
- **Q33 처리 원칙**: 조사 대상 2개 후보 모두 전 조건 완전 충족에 도달하지 못할 경우, 자의적으로 조건을 완화하지 않고 **'공개 보류 입력(Holding Input)'**으로 판정하며, 조건별 미충족/미확인을 분리 보고하고 인간 운영자(HITL)에게 후속 선택 쟁점을 제시함.

### 1.4 출처 확인 방식 및 환경 제약 (Verification Methodology & Constraints)
본 조사는 curl/urllib 기반 정적 HTML 본문 추출과 웹 검색 데이터를 바탕으로 수행되었으며, 다음의 환경적 한계를 명시한다.
1. **정적 본문 확인 (Static Text Verified)**:
   - NCP: High CPU `c2-g2` 인스턴스 규격(2개 vCPU, 4GB RAM, 50GB 디스크), 한국 리전, 무료 OS 이미지(Ubuntu, Rocky), 공인 IP 단가(5.6원/시간, 4,032원/월), 트래픽 구간 구조(20GB 무료 후 과금), 정지 시 디스크 요금 청구 문구.
   - Cafe24: VPS 정의, root 권한 정의, 백업 미지원 및 고객 직접 백업 책임 FAQ, 서비스 취소/해지 시 즉시 자료 삭제 FAQ, 콘솔 외부 방화벽 2가지 INBOUND 정책 및 리눅스 `iptables` 보안 가이드.
   - NHN Cloud: 한국(판교/평촌) 리전 선택자.
   - Hosting.kr: `.co.kr` 및 `.kr` 신규 등록 요금 20,000원/년(VAT 별도), 무료 네임서버 제공 문구.
   - 카카오/네이버: 약관 본문 내 메일 데이터의 물리 데이터센터 위치 미명시 사실.
2. **동적 렌더링 의존 ([미확인: JS 렌더링/동적 로드])**:
   - NCP: 서버 시간당 96원 및 월 69,120원, 아웃바운드 초과 GB당 100원, Object Storage GB당 28원, 정지 시 디스크 단가(100원/GB) (공식 페이지 표의 요금 셀이 JS 컴포넌트로 구현되어 정적 본문 미기재).
   - Cafe24: 가상서버 '자이언트'의 4GB RAM / 100GB SSD / 1.2TB 스펙 및 월 33,000원 이용료, 초기 설치비 20,000원 (상품 안내 페이지가 842바이트 JS 셸 리다이렉트 구조로 정적 본문 미기재).
   - NHN Cloud: Object Storage 요금표 및 S3 호환/수명주기 상세 (공식 가이드가 봇 접근 시 리다이렉트 처리되어 정적 확인 불가).
   - Hosting.kr: 도메인 갱신(기간연장) 가격 (신규 등록가만 정적 확인, 갱신가는 JS 동적 로드).
3. **비용표 성격**:
   - 본 보고서의 비용 계산표는 웹 UI/검색 스니펫 상의 요금 단가를 반영하여 실무적 검토 목적으로 작성되었으나, 단가 다수가 정적 텍스트로 확증되지 않았으므로 **'미확인 입력 기반 추정치 (Estimated based on unverified JS-rendered inputs)'**로 분류한다.

### 2.1 후보 1: 네이버클라우드 (NCP) 조합 상세

## 5. 의존성 격리, 보관 및 복구 사실 분석 (Isolation & Recovery)

### 5.1 계정, 인증, 장애 도메인의 실제 독립성
- **자격증명 독립성**:
  - VM 콘솔 계정 (네이버클라우드 / 카페24)
  - 도메인 관리 계정 (호스팅케이알)
  - 주 운영메일 계정 (카카오)
  - 예비 운영메일 계정 (네이버)
  - 독립 공지 관리 계정 (GitHub)
  - 상기 5개 계정은 서로 다른 사업자의 플랫폼이며 각각 독립된 사용자 식별자 및 2단계 인증을 사용함.
- **복구 순환 참조 방지**:
  - 도메인 등록처(호스팅케이알)나 독립 공지(GitHub)의 비밀번호 재설정 이메일로 자체 서비스 도메인(`@eduvibe.kr`)을 지정하지 않고 외부 포털 메일로 지정함으로써, 자체 도메인/DNS 장애 시 계정 복구가 불가능해지는 순환 의존성을 차단함.

### 5.2 공급자 백업 vs 고객 제어 백업과 30일 보관
- **공급자 백업 정책**:
  - 카페24 가상서버는 공식 FAQ에 명시된 바와 같이 "별도의 백업을 지원하지 않으며, 고객이 직접 백업"해야 함 ([백업 FAQ](https://help.cafe24.com/faq/server-hosting/virtual-server-hosting/service-inquiry/vps-backup-policy-and-initialize-os)).
- **고객 제어 백업**:
  - 운영자가 VM 내부 cron 작업을 통해 SQLite 데이터베이스를 암호화 아카이브로 생성한 후, 타사 오브젝트 스토리지(NCP 또는 NHN Cloud)로 업로드하는 구조를 전제함.
  - 단, 30일 수명주기 만료 객체 자동 삭제 규칙은 제품 소개 정적 본문에서 확인되지 않았으며 가이드 문서 확인이 필요함 ([미확인]).

### 5.3 공급자 문서상의 삭제 및 해지 시 데이터 처리
- **카페24**: [취소/해지 FAQ](https://help.cafe24.com/faq/best-questions/cancel_or_terminate_hosting_service)에 따르면 "서비스 취소/해지 신청 시 즉시 모든 자료가 삭제되며 복원이 불가"하다고 명시되어 있음 (정적 텍스트 확인).
- **네이버클라우드**: 콘솔에서 인스턴스 반납 시 기본 옵션에 따라 연결된 스토리지 블록이 함께 회수 및 삭제 처리됨.

### 5.4 RPO 24시간 / RTO 48시간 복구 목표 및 훈련 제약
- **복구 목표 평가**:
  - RPO 24시간 및 RTO 48시간은 공급자 문서상의 보증이나 SLA가 아니며, 운영 정책상의 목표임 ([미확인]).
  - 카페24는 [백업 FAQ](https://help.cafe24.com/faq/server-hosting/virtual-server-hosting/service-inquiry/vps-backup-policy-and-initialize-os)에서 "보유 중인 데이터 백업이 있다면 복원이 가능합니다"라고 안내하고 있으나, 구체적인 시간 단위 복구 보증은 명시되어 있지 않음.
- **복구 연습(Drill) 평가 범위**:
  - 분기 1회 호스트 상실을 가정한 복구 연습(Q26)에 필요한 구체적 추가 비용 및 대체 환경의 적합성은 **본 연구의 조사 범위에서 평가하지 않음 (미평가/미확인)**. 실제 연습 환경 구성 및 비용 발생 여부는 후속 운영 검증 과제로 남김.

> Q33의 명령에 따라 본 연구 결과를 **"공개 보류 입력"**으로 최종 기록하며, 임의로 예산, 저장 지역, 분리, 하드웨어 조건을 완화하지 않는다.

### 7.2 사람(운영자/조정자)이 결정해야 할 핵심 쟁점 및 후속 후보 조사안

확인된 사실과 미확인 한계에 근거하여 운영자(사람)가 결정해야 할 쟁점은 다음과 같다.

   - 정적 텍스트로 확증되지 않은 자이언트 플랜의 스펙 및 가격(JS 셸)을 실제 결제 콘솔 화면 확인을 통해 확정할 것인가?
3. **[쟁점 3] 운영메일의 물리 저장 위치 미명시 수용 여부**:

5. **[쟁점 5] Q33에 따른 추가 후보 조사 진행 여부**:
   - 기존의 조건(2vCPU/4GB, 국내 저장, 분리 백업, 월 5만 원 이하)을 유지한 상태에서, 아래의 추가 후보들에 대해 후속 조사를 진행할 것인가?
     - **스마일서브 (iwinv)**: 국내 클라우드 가상서버 (사람의 선택에 따른 후속 조사 대상 후보)

     - **NHN Cloud**: 국내 클라우드 인스턴스 저사양 라인업 (사람의 선택에 따른 후속 조사 대상 후보)
